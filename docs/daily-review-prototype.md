# 데일리 리뷰 화면 시안

## 범위

- 경로: `/daily-review` (독립 일반 메뉴 → 데일리 리뷰). 관리자 권한이나 로그인 없이 접근할 수 있다.
- 모바일 전용 미리보기: `/daily-review/mobile`. 데스크톱에서도 최대 430px 너비로 모바일 레이아웃을 비교할 수 있으며, 기본 화면도 화면 너비에 따라 반응형으로 표시한다.
- 이전 `/admin/MH/daily-review` 주소는 `/daily-review`로 리디렉션한다.
- 사용자의 요청에 따라 데이터 확보 전에 리뷰 흐름을 검토하는 화면을 구현했다.
- 모든 뉴스, 발표일, 가격, 차트, AI 해석은 합성 예시다. 실제 데이터 조회, AI 호출, DB 변경, 스케줄 등록, 배포는 포함하지 않는다.
- 2026-09-23 / 2026-09-22 두 예시 날짜를 선택할 수 있다. 실제 해당 날짜의 시황을 뜻하지 않는다.

## 동작

1. 시장 뉴스: 중요도 순의 사건 목록, 분류 필터, 읽음, 안 읽은 사건만 보기, 선별 이유와 출처 구성 펼치기. 건수 제한 없음.
2. 경제지표: 발표가 있는 날 CPI 예시 카드(MoM/YoY, 계절조정 구분, 추이, AI 해석), 발표 없는 날의 빈 상태.
3. 매크로: 금리/환율/원자재 분류와 개별 자산 선택.
4. 위험 심리: VIX/금/BTC 선택.
5. 지수: S&P 500/나스닥/다우/러셀/SOX 선택.
6. 대형주 검토: 일반 이용자가 접근하는 기존 `/chart`로 연결. 새로운 종목 검토 페이지는 만들지 않음.
7. 리뷰 메모: 날짜별 메모와 확인 표시를 명시적인 저장 버튼으로 localStorage에 보관. 기기 간 동기화와 계정별 분리는 미구현이며 화면에 브라우저 저장임을 안내한다.

상단에서 새 발표 / 발표 없음 / 가격 수집 지연 상황을 전환할 수 있다. 지연 상황에서는 현재 가격 및 등락률을 표시하지 않는다.

기존 `IndexLineChart`를 재사용하고 선택적인 `pricePrecision`을 추가했다. 기본 차트 사용처의 설정은 그대로 유지하며 새 리뷰에서는 환율·금리 등의 소수점 정밀도를 지정한다. 금리 변화는 bp, 가격 변화는 %로 구분한다.

전역 상단 메뉴는 일반 서비스, 관리자 드롭다운, 계정 메뉴로 정리했다. 모바일에서는 스케줄러·데일리 리뷰·기업 분석과 전체 메뉴 버튼을 표시한다. 전체 메뉴는 모달로 열리며 Escape와 닫기 버튼으로 닫힌다. 관리자 및 개인 위키 메뉴의 기존 권한 조건은 유지한다. 리뷰의 모바일 섹션 이동과 자산 선택은 가로 스크롤 대신 줄바꿈하는 격자로 구성했다.

## 데이터 연결 전 결정할 것

- 자산별 정확한 상품, 공급원, 일봉 시간대, 최신값 도착 시각.
- 현물/선물 구분, 선물 계약 교체, 확정 일봉과 리뷰 시점 스냅샷 구분.
- 발표 관측 기간, 발표 시각, 수집 시각, 수정 이력과 예상치 출처.
- 뉴스 중요도 기준, 사건 묶음, 원문 출처, 수집 실패 표시.
- 실제 데이터 및 개인 메모를 연결하기 전 공개 시황과 사용자별 저장 범위. 현재 일반 페이지에는 공개 가능한 합성 예시만 포함한다.

뉴스 수집·선별·저장 원칙은 [데일리 리뷰 뉴스 수집 계획](./daily-review-news-plan.md)을 따른다. 중요도 기준을 통과한 사건과 근거 기사 참조만 날짜별로 보존하고, 전체 원문은 영구 저장하지 않는 방향을 사용자가 승인했다. 실제 RSS/AI/DB 연결은 별도 구현 단계에 있다.

## 검증

- 로컬 브라우저에서 뉴스 필터, 발표 없음, 가격 지연, 환율 자산 전환 확인.
- 메모와 확인 표시 저장 후 새로고침 복원 확인. 검증용 메모 정리.
- 390×844 모바일 화면에서 뉴스와 CPI 레이아웃, 차트, 섹션 이동 확인.
- 비로그인 상태에서 새 일반 경로와 모바일 미리보기 접근 확인. 390px 화면의 문서 너비가 390px임을 확인했고 전체 메뉴 열기·Escape 닫기·초점 복귀를 확인했다.
- 이전 MH 주소에서 일반 주소로 실제 이동하는 것을 확인했다. 변경한 메뉴·레이아웃·리뷰 페이지에 대한 ESLint 검사는 통과했다.
- 프로덕션 빌드 성공. 저장소 설정상 빌드가 타입 검증을 생략하므로 별도 `tsc --noEmit`도 수행했고 기존 파일의 오류를 확인했다.
- 전체 `npm run lint`는 메모리 부족으로 종료. `eslint src`는 기존 코드 오류를 보고했다. 새 페이지 및 수정 파일은 별도 범위 검사로 검증한다.
