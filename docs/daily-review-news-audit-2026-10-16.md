# 데일리 뉴스 업데이트 점검 — 2026-10-16

대상: DB `market_data.daily_review_news_runs`에서 조회한 2026-10-14~16의 실행 5건, 관련 수집·발행 스크립트 및 공개 읽기 API 코드. 데이터 조회만 수행했으며 수집기·자동화·기존 리뷰를 변경하지 않았다. 뉴스 이외 경제지표·시장가격 수집의 운영 감사는 이번 범위가 아니다.

최초 실행은 상세 설명 강화 요청 이전의 기준이다. 강화 이후에도 짧은 설명이 많다. 800~1,500자는 기본 목표이고 근거 부족 시 짧게 쓰는 예외가 있으므로, 글자 수만으로 개별 사건의 품질 실패를 확정하지 않는다.

저장된 실행은 모두 검토·발행 완료이며 후보 전문은 사건 근거 메타데이터에 포함되지 않는다. 이 기록만으로 예약 누락이나 DB 등록 이전 수집 실패가 전혀 없었다고 판단할 수는 없다.

## 관측한 한계

1. 발행시각 누락이 지속된다. 한겨레 3개 피드, 일부 실행에서는 경향 3개 피드도 `SOURCE_PUBLISHED_AT_MISSING` 상태다. 최신 실행 선택 근거 138건 중 21건에 발행시각이 없다. 수집기는 시각 없는 항목을 후보로 유지하므로 정확한 24시간 포함 여부를 보장할 수 없다. PARTIAL 표시는 존재하지만 해당 오류가 여러 날 지속된다.
2. 제목·RSS에 머무는 사건이 있다. 최신 선택 근거 138건 중 34건은 Google News 경유 URL이고, 실제 원문 최종 URL·확인 시각·검증 수준을 구조화해 저장하지 않는다. Google 링크 자체가 미검증의 증거는 아니지만 원문 확보·확인율을 DB만으로 계산하기 어렵다. 일부 설명은 확인하지 못한 항목과 일반 영향 경로가 실제 사건 정보보다 큰 비중을 차지한다.
3. 길이·독립적 이해 가능성 검증이 발행 조건이 아니다. publisher는 details 문자열이 비어 있지 않은지만 확인한다. 핵심 사건 원문 확보, 사실별 근거, 상투 문단 여부는 편집자의 판단에 의존한다. 전체 후보 검토도 ID 완전성 및 편집자의 기록을 검증할 뿐 실제 이해·누락 부재를 입증하지 않는다.
4. 사건과 테마 묶음이 혼재한다. 최신 `china-chips`에 중국 메모리·노광 부품·SK하이닉스 미국 투자 조건이 함께 있고, `new-chip-design`에는 Arm·구글·파두의 별도 제품 발표가 묶였다. 각 회사 사건의 변화·근거·중요성을 읽기 어렵다.
5. 신규·후속·재게시를 구분하지 않는다. 10/15 오전→오후에 상세 설명 10건, 10/15 오후→10/16 오전에 8건이 동일하다. 최근 24시간 창의 중복 자체는 정상이나 새로 바뀐 부분을 식별하는 구조가 없다. 사건 ID도 일관된 장기 연결 키로 보장되지 않는다.
6. 재현·운영 감사가 제한된다. 원시 후보와 manifest는 최신 파일로 교체되고 selection·추가 검증 원문은 /tmp에 남는 방식이다. DB hash와 후보 수만으로 과거 제외 후보 전체와 당시 제목·본문 버전을 복원할 수 없다. 공개 API는 날짜별 최신 실행 하나만 반환하며 이전 실행 비교 API가 없다. 예약 슬롯별 시작·실패·완료와 원문 검증 수준을 별도 집계하지 않는다.
7. 피드 의존에 따른 누락률은 미측정이다. RSS가 노출한 후보의 전체 검토와 전일 시장의 모든 중요 사건 수집은 다르다. CPI/PPI 공식 대조 등 실제 검증은 있으나 주요 발표·실적·시장 마감 체크리스트와 대조해 누락을 계량한 기록은 없다. 후보 1천여 건 자체가 충분한 커버리지를 입증하지 않는다.

## 개선 우선순위 — 제안, 미구현

1. 원문 최종 URL·확인 시각·근거 유형·검증 상태와 발행시각 보완을 구조화한다. 핵심 사건은 원문/공식자료 확보를 우선하고 부족하면 명확히 표시한다. 불확실성 경고로 분량을 채우지 않는다.
2. 한 사건 단위로 나누고 관련 사건은 별도 테마로 연결한다. 신규·후속·변경 없음과 변경 요약을 관리한다. 수량 상한이나 지역 할당은 두지 않는다.
3. 예약 슬롯·시작·완료·실패 및 마지막 성공 시각을 기록한다. 과거 실행 비교와 제한적 입력 감사 보존을 추가한다. 전문 영구 저장 대신 후보 메타데이터와 선택·제외·검증 기록을 우선 검토한다.
4. 미국장 마감·공식 주요 지표·대형 실적의 발표 일정과 검토 결과를 대조한다. 06시 실행은 정시 이전에 시작해 마감 전 후보를 수집할 수 있으므로 시장 마감 데이터 확정 여부를 별도 확인한다. 실제 10/15 수집은 05:57이었다.

## 첫 보강 결과 — 같은 날 구현·검증

- 새 `daily_review_news_evidence.py`와 `daily_review_news.py prepare`를 추가했다. 기존 외부 RSS 수집기 자체를 수정하지 않고 선정 근거의 원문 URL·JSON-LD/메타 발행시각·본문 후보를 확보하는 단계를 덧붙였다. Google 신규 형식은 공개 페이지의 URL 응답을 시도하지만 접근 제한 등으로 실패할 수 있다.
- 실제 기사 3건 시험에서 국내 2건의 본문 후보·시간대가 있는 발행시각을 추출했고 Google 경유 1건은 실패로 기록했다. 3건 모두 성공했다고 표시하지 않는다. 본문 후보 획득과 편집자의 읽기·검증은 별도 상태이다.
- 신규 발행은 선정 근거 전부의 조회 시도가 있어야 한다. 핵심 사건에 직접 읽은 후보 근거가 없으면 구체적 예외 설명을 요구하고 confidence에 추가 확인 필요를 붙인다. 공개 API가 기존 confidence를 표시하므로 별도 신규 화면 배포는 필요하지 않다. 설명 길이·핵심 미확인 목록도 DB audit에 남긴다.
- 사건별 메타데이터는 허용 필드만 저장해 본문 필드가 유입돼도 DB로 복사하지 않는다. 본문은 OS 임시 파일에 둔다. 새 수집부터 후보 메타데이터 목록을 run별 로컬 파일로 보존한다.
- 수정시각을 발행시각으로 쓰지 않는지, 상충 시각을 보류하는지, 내부 IP URL을 차단하는지, 분기→월간 오설정을 탐지하는지, 미조회 근거·읽지 못한 근거의 허위 읽기 신고를 거부하는지, 핵심 근거 예외 표시·본문 비저장을 검증한 테스트 8개 통과.
- 기존 뉴스 API의 2026-10-16 실행 ID와 사건 수 48건 보존 확인. 기존 리뷰를 enrich하거나 다시 발행하지 않았다.
- 경제지표는 별도 `docs/daily-review-fred.md`에 기록했다. 실제 월간 실질소비 누락을 수정했고 54종 원천 CSV/DB 최신 날짜·값 비교에서 불일치 0건, 공개 경제 API에서 54종과 수정된 빈도를 확인했다.
- 미구현: 신규/후속 UI, 정규화한 장기 사건 연결 키, 자동 발표 일정 대조, 예약 슬롯별 감시와 원문 검증률 UI. 이번 보강으로 모든 기존 감사 지적이 해결됐다고 주장하지 않는다.
- 추가 검증: Python 문법 검사·변경 파일 공백 검사 통과. `npm run build -- --webpack` 프로덕션 빌드 통과. 기본 Turbopack 빌드는 최적화 단계에서 진척이 없어 중단했으며 성공으로 기록하지 않는다. 배포·커밋·푸시는 수행하지 않았다.
