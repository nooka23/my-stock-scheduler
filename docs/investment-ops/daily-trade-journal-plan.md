# 나무·영웅문 국내/해외 매매일지 및 예수금 자동 기록 계획

- 작성일: 2026-10-12 KST
- 상태: 사용자 구현 요청으로 저장 구조·표준 데이터 가져오기·매매일지 UI 구현, self-host DB 적용 완료. 실제 증권사 연동·예약 작업은 API 신청/키 발급 대기. 상세 검증은 [trade-journal-setup.md](trade-journal-setup.md).
- 사용자 요구: 나무와 영웅문에서 거래하는 국내/해외주식의 거래내역을 매일 특정 시점에 수집하고 예수금 이력을 기록.
- 사용자 확정: 현재 해외는 미국주식만, 향후 다른 국가 확장 가능성 있음. 계좌는 나무 일반 1개·나무 ISA 1개·키움 1개(총 3개).
- 사용자 확정: 수집 시각은 KST 오전 6시·오후 4시. 나무 신청·발급 완료, 키움은 배우자 계좌로 추후 인증 후 추가. 첫 연동 범위는 나무 일반/CMA(사용자가 확인한 끝자리 2466)이며 ISA는 추가 대기, 키움은 추후 인증까지 비활성화.
- 미확정: 키움 계좌 유형, 과거 이관 기간, 키 발급 후 실제 조회 범위.
- 기존 검토: [provider-decision.md](provider-decision.md). 이번 문서는 일별 기록 범위를 구체화하며, 기존 장중 위험관리/거래 전 자산 검증이나 LIVE 전환 조건을 충족했다고 간주하지 않는다.

## 1. 권장 방식과 확인 수준

증권사 공식 REST API → 계좌별 수집기 → 정규화·중복 방지 → Supabase 원장/잔액 이력 → 매매일지 화면.

첫 구현은 국내·미국과 3개 계좌를 대상으로 한다. 나무 일반, 나무 ISA, 키움을 별도 계좌로 관리하고 계좌별 잔고/손익과 통합 조회를 제공한다. ISA는 국내 자산 조회부터 검증하며 ISA의 API 등록·조회 가능 여부를 별도 확인한다. 계좌 유형에 따른 세금·손익 의미를 같은 것으로 취급하지 않는다.

미래 국가 확장에 대비해 시장/거래소·통화·시간대·거래/결제일을 데이터에 명시하고 증권사별 지원 범위를 설정으로 관리한다. 일본/홍콩/중국 수집기를 지금 구현하는 범위는 아니다. 국가를 추가할 때 해당 API 지원과 결제/거래일 규칙을 검증한다.

HTS/MTS에서 직접 실행한 거래도 포함되는지 실제 계좌 조회로 확인한다. API 문서에 조회 기능이 존재한다는 사실만으로 모든 계좌·주문 경로·세션·통화가 지원된다고 확정하지 않는다.

| 구분 | 공식 공개 문서에서 확인한 기능 | 구현 전 검증 |
|---|---|---|
| 나무 국내 | NAMUH PLUG 국내 체결, 잔고, 자산현황, 공통 종합거래/입출금 조회 | 계좌 유형별 이용 가능 여부, 체결 식별자, 통화별 잔액 필드 |
| 나무 해외 | 해외 체결, 잔고, 일별거래내역 | 실제 거래 국가·통화, 소수점 및 주간/야간 거래 포함 여부 |
| 키움 국내 | REST 체결/주문체결내역, 예수금, 종합거래내역, 평가잔고 | KRX/NXT·HTS/MTS 등 모든 실제 거래 경로 포함 여부 |
| 키움 미국 | REST 일별 주문체결, 거래내역, 해외 예수금, 통화별 예수금/평가금 | 정규·프리·애프터·주간 거래, 환전·입출금 분류, 거래일 정의 |
| 키움 미국 외 | 공개 REST 서비스 소개의 상품 범위는 국내·미국 주식 | 사용 시장 확인 후 지원 API 또는 HTS 파일 경로 별도 검증 |

키움 조회 후보: 국내 `ka10076`, `kt00007`, `kt00001`, `kt00015`, `kt00018`; 미국/해외 현금 `ust21150`, `ust21100`, `ust21110`, `ust21120`, `ust21160`. 이 코드는 공식 가이드 목록의 후보이며 필드 매핑이 확정된 것은 아니다.

나무는 고객번호당 APP KEY 하나로 여러 계좌를 사용할 수 있다고 안내한다. 키움은 계좌 APP KEY 등록과 허용 IP 등록 절차를 안내한다. 실제 계좌별 자격·인증 요건은 신청 시 확인한다.

API 누락 범위와 과거 내역은 HTS CSV/Excel 가져오기로 보완한다. 파일 내보내기를 사용자가 해야 한다면 해당 경로는 반자동으로 표시한다. 화면 OCR은 숫자·통화·중복 검증이 어려우므로 보조 입력으로만 고려한다.

## 2. 현재 프로젝트에서 확인한 사항

- `src/app/admin/MH/portfolio/page.tsx`의 현금은 `localStorage['portfolio_cash']`에 저장되는 수동 단일 값이다. 계좌/통화별 서버 원장이나 잔액 이력이 아니다.
- 마이그레이션의 `user_portfolio_transactions`는 SELL 제약이 있는 매도 이력이다. 자동 매수/매도·입출금 원장을 그대로 끼워 넣기 어렵다.
- `scripts/investment_ops`에는 설정/로깅/Decimal 및 시간 처리 기반이 있다. 재사용하되 증권사 수집 기능이 구현된 것으로 간주하지 않는다.
- 국내/미국 시세용 launchd 설정 파일이 존재한다. 증권계좌 수집은 별도 작업으로 운영한다. 이번 확인은 파일 검사이며 현재 작업의 실행 여부를 검증한 것은 아니다.
- 기존 KIS 코드는 시세 수집용이다. 한국투자증권 API로 나무/키움 계좌를 읽는 구조를 사용하지 않는다.

## 3. 사용자 확정 수집 시각

모든 아래 시간은 한국시간이다. 사용자 결정으로 기존 20:30/10:30 제안을 06:00/16:00으로 변경했다. 코드 설정과 화면에 반영했으며 실제 예약 작업은 키 발급 후 등록한다.

| 시간 | 목적 | 처리 |
|---|---|---|
| 매일 06:00 | 미국 거래 오전 관측 및 전체 계좌 갱신 | 미국 거래일별 해당 시각까지 반영된 체결·현금·잔액 재조회 |
| 매일 16:00 | 국내 거래 오후 관측 및 전체 계좌 갱신 | 국내 거래와 오전 이후 해외 거래·현금 변동 보완 |
| 매주 1회 | 누락 및 사후 정정 점검 | 조회 가능 범위 내 최근 30일 원장과 증권사 잔고 대조 |

- 최근 7일을 겹쳐 재조회하는 방식을 초기 후보로 삼되 API의 조회 보존기간·기간 제한에 맞춘다. 주간 30일 조회도 지원 여부를 먼저 확인한다.
- 휴일에도 현금 조회를 시도하되 증권사 점검시간/영업일 가용성을 반영한다. 실패한 조회는 거래 없음으로 처리하지 않는다.
- 오전 6시 이후 해외 거래, 오후 4시 이후 국내 거래 및 API 반영 지연분은 다음 수집에서 보완한다. 서머타임·휴장·단축장에 따라 세션이 진행 중일 수 있으므로 두 시각 모두 거래일 전체 완료를 뜻하지 않는다. 실제 관측시각의 잔액을 전일 종가 잔액으로 표시하지 않는다.
- `executed_at`(UTC), 원본 시간대/시각, 증권사 `trade_date`, `settlement_date`, `observed_at`을 구분한다. 거래일을 KST 날짜로 임의 치환하지 않는다.
- 조회 시점에 진행 중인 세션은 임시 기록으로 보여주고 다음 조회에서 보완한다. 수수료·세금·결제 내역은 나중에 확정될 수 있다.
- 작업 누락 시 다음 실행에서 마지막 성공 구간부터 따라잡는다. 보존기간을 넘긴 누락은 파일 복구 대상으로 표시한다.

## 4. 기록 데이터

### 체결과 매매일지

- 사용자, 증권사, 계좌 별칭, 시장/거래소, 종목 식별자, 통화.
- 매수/매도, 원주문/주문/체결 식별자, 부분체결 수량·가격·금액, 거래·결제일, 수수료·세금 및 확정 상태.
- 정정/취소 주문과 이미 발생한 체결 취소·정정의 의미를 구분한다. 미체결 주문을 매매로 기록하지 않는다.
- 화면은 체결 원본과 주문/종목/일자별 요약을 모두 제공한다. 매수와 매도는 서로 상계해 숨기지 않는다.
- 매매 이유, 전략, 복기, 손절 기준은 별도 사용자 메모로 저장하며 재수집이 덮어쓰지 않는다. 실제 의도를 AI가 추정해 확정 기입하지 않는다.
- 손익은 증권사 제공 값과 자체 계산 값을 구분한다. 자체 계산은 원가법, 수수료·세금 포함 여부, 외화 환산 시점이 정해진 뒤 제공한다. 입금을 수익으로 계산하지 않는다.

### 예수금: 잔액과 변동 원장 모두 필요

| 범주 | 저장 항목/원칙 |
|---|---|
| 통화별 잔액 | KRW, USD 및 실제 사용 통화의 예수금·출금가능금액·주문가능금액을 각각 보관 |
| 결제 예정 | API가 제공하는 D+1/D+2 등의 원본 의미와 실제 결제 예정일·금액 보관. 해외에도 국내 결제 규칙을 일괄 적용하지 않음 |
| 현금 변동 | 입금, 출금, 매매 결제, 환전, 배당, 세금, 수수료, 이자, 기타 조정 |
| 환전 | 출발/도착 통화와 금액, 적용환율, 수수료, 연결 식별자. 증권사 원장과 자동환전 내역 중복 방지 |
| 자산 평가 | 통화별 주식 평가액과 증권사 총자산의 정의를 보관. 주문가능금액을 총자산으로 사용하지 않음 |
| 원화 환산 | 원통화 잔액 보존, 사용 환율·시각·출처를 별도 기록. 총 원화 평가액을 통화 잔액에 다시 더하지 않음 |

동일 계좌를 국내/해외 API 양쪽에서 조회할 때 겹치는 원화 예수금과 통합증거금·원화대용은 한 번만 합산한다. 예수금·매수가능금액·출금가능금액은 서로 더하는 항목이 아니다.

자동 RP/CMA 운용, 신용·미수·대출, 배당/기업행사, 주식 입출고가 있으면 별도 이벤트로 구분해야 한다. API가 해당 항목을 제공하지 않으면 누락 범위를 표시한다. 계좌 간 이체는 계좌별 입출금으로 기록하고, 전체 통합 성과 계산에서는 내부 이체를 제거한다.

통화별 전기 잔액에 실제 현금 변동을 더한 결과를 동일 기준의 현재 잔액과 대조한다. 체결일에 계산한 매매대금과 결제일의 현금 원장을 동시에 현금에서 차감하지 않는다. 미설명 차이를 임의 조정 항목으로 만들어 맞추지 않는다.

## 5. 저장 및 연결 설계

논리적 데이터 영역 제안이며 테이블명/마이그레이션은 아직 확정하지 않았다.

| 영역 | 역할 |
|---|---|
| 증권계좌 | 소유자, 증권사, 계좌 별칭/유형, 인증정보 참조, 연동 범위 |
| 수집 실행/원본 | 요청 범위, 페이지 완결성, 상태, 해시, 필요한 원본 필드의 비밀정보 제거 후 보관 |
| 체결 원장 | 체결 단위 불변 식별자와 정정 이력 |
| 현금 변동 원장 | 통화별 입출금·환전·배당·매매 결제 등 |
| 잔액/보유 스냅샷 | 계좌·통화·실제 관측 시점별 잔액과 종목 수량 |
| 일지/메모 | 자동 요약, 사용자의 판단·복기, 원장과의 연결 |

기존 포트폴리오는 초기 병행 운영 중 그대로 두고 새 원장과 비교한다. 연결 시 전환 시점의 실제 보유잔고를 기초잔고로 삼거나 전체 과거 체결을 재구성하는 방식 중 하나를 선택한다. 기초잔고에 과거 매수를 다시 더하지 않는다. 기존 수동 매도 이력과 자동 수집 체결도 대조표로 연결해 중복을 방지한다.

과거 현재가/잔액 조회로 과거 일별 잔액을 재현할 수 있다고 가정하지 않는다. API가 과거 기준일 잔액을 제공하는 범위만 이관하며 나머지는 자동화 시작일부터 축적한다.

## 6. 정확성과 운영

- 체결 키는 증권사+계좌+원본 거래일+검증된 체결 식별자를 기본 후보로 한다. 주문번호 하나만으로 중복 제거하면 부분체결이 사라질 수 있다.
- 고유 체결 ID가 없으면 공식 행 식별/순번 의미를 확인하고 동일 시각·가격·수량의 별도 체결을 구분하는 규칙을 검증한다. 파일 해시만으로 서로 겹치는 파일/API 거래 중복을 제거할 수 없다.
- 연속 조회의 마지막 페이지까지 성공해야 해당 범위를 완료 처리한다. 일부 페이지 실패 시 기존 성공 데이터를 보존하고 범위를 미완료로 남긴다.
- Decimal과 DB numeric 사용. 소수점 주식 정밀도는 증권사 원본에 맞춘다. 미제공 수수료/세금은 0이 아니라 미확정 값이다.
- 토큰 만료 재발급, 증권사 호출 제한, 재시도/지수 백오프, 동시실행 잠금, 계좌별 실패 격리를 구현한다.
- 수집 실패 시 잔액을 0으로 덮어쓰지 않는다. 마지막 성공 시각과 최신성/미완료 상태를 표시한다.
- 실제 체결 건수·수량·금액과 수수료·세금 합계, 보유수량, 통화별 잔액을 증권사 화면/내보내기와 대조한다. 주식 분할·입출고는 체결 없이 수량이 변하는 사례로 처리한다.
- 실행 환경은 기존 Mac의 별도 launchd 작업을 우선 후보로 한다. 항상 켜짐/잠자기/재부팅 후 복구와 허용 외부 IP 안정성을 확인한다. 충족하지 못하면 고정 출구 IP를 가진 상시 서버를 검토한다.
- 시크릿은 Keychain 또는 서버 비밀 저장소에 보관하고 브라우저·로그·Git에 노출하지 않는다. DB/UI는 계좌 소유자 권한을 적용한다.
- 수집기는 조회 엔드포인트 허용 목록만 사용한다. API 키 자체에 조회 전용 권한이 제공된다고 가정하지 않으며 주문·환전 실행 기능은 이 계획에 포함하지 않는다.
- 알림이 필요하면 실패·장기 미수집·잔액 불일치를 대상으로 별도 채널을 정한다. 이번 계획에서 메시지 전송/알림 작업을 등록하지 않았다.

## 7. 구현 단계와 완료 조건

| 단계 | 작업 | 완료 판단 |
|---|---|---|
| 1. 접근/범위 확인 | 양사 API 신청 상태, 계좌 유형, 국가, 조회 기간 확인 | 실제 대상 계좌에서 체결·현금·잔액을 조회할 경로 확정 |
| 2. 읽기 검증 | 양사 국내/해외 체결·잔액·거래내역 샘플 및 전체 페이지 확인 | HTS/MTS 거래 포함, 부분체결/거래일/통화/필드 의미 확인 |
| 3. 원장/수집기 | 스키마, 양사 어댑터, 재수집·중복 방지·정정 처리 | 같은 자료 반복 수집 시 중복 0, 실패 페이지 복구 및 이력 보존 |
| 4. 일지/예수금 화면 | 날짜·계좌·시장 필터, 현금 이력, 메모, 수집 상태 | 매수/매도 및 통화별 잔액을 증권사 자료와 대조 가능 |
| 5. 병행 검증 | 최소 5거래일 권장, 실제 발생 사례 추가 확인 | 설명되지 않은 거래/잔고 차이 0, 장애 재실행 복구 확인 |
| 6. 정기 운영 | 제안 시각 조정 후 예약, 과거 이관 및 기존 포트폴리오 연결 | 대상 계좌/시장 커버리지 표시, 잔액 최신성/누락 감지 동작 |

5거래일은 관찰 기간 제안이며 그 기간이 지났다고 검증 완료로 판단하지 않는다. 실제 계좌에서 없는 사례를 만들기 위해 거래하지 않는다. 누락된 중요 사례/지원 범위는 미검증으로 표시한다.

이번 일별 스냅샷은 장중 특정 거래 직전의 총자산 증거를 대신하지 않는다. 기존 투자규칙 자동 평가나 포지션 자동 변경은 별도 검증 범위다.

## 8. 다음 결정 항목

1. 두 API 서비스의 신청/키 발급 여부. 비밀값을 문서나 채팅에 기록하지 않는다.
2. 나무 ISA의 API 조회 자격 및 키움 계좌 유형 확인. 계좌번호는 계획에 불필요.
3. 과거 내역 이관 기간. 수집 시각은 KST 06:00/16:00으로 사용자 확정.

사용자가 확정한 현재 대상은 나무 일반 1개·나무 ISA 1개·키움 1개, 해외는 미국주식이다. 미래 해외시장 확장 가능성을 구조에 반영하되 현재 필수 범위에 추가하지 않는다.

사용자가 과거 수익률 계산을 제외하고 현재 잔고 저장만 우선 요청했다. 일반/CMA의 현재 보유 포지션 11개(국내 1·미국 10)와 KRW/USD 예수금을 소유자 계정에 저장하고 읽기 일치를 확인했다. 현재 잔고를 가상의 매수나 과거 거래로 변환하지 않는다. 현재 화면은 증권사 관측 잔고 및 평가손익만 보여주며 과거 수익률은 계산하지 않는다. ISA·키움은 추가 대기이고 06:00/16:00 KST 자동 수집은 아직 활성화하지 않았다. 상세 구현/검증은 `trade-journal-setup.md`에 기록했다.
