# 매매일지 구현 및 연결 현황

2026-10-12 KST. 사용자 요청에 따라 구현 착수. 수집 시각은 한국시간 **06:00·16:00**으로 확정.

## 현재 구현·검증한 범위

- 계좌: 나무 일반 1개, 나무 ISA 1개, 키움 1개. 시장: 국내·미국.
- 사이트 경로: `/admin/MH/trade-journal`, 사이드바 MH 분석 → 매매일지.
- 화면: 계좌/시장/거래일 필터, 페이지별 체결, 통화별 현재 예수금/출금가능/주문가능, 한국 날짜별 예수금 관측/현금 변동, 거래별 복기 메모.
- DB: 계좌·배치 감사이력·체결·현금 변동·잔액·메모의 6개 테이블과 최신잔액 view, 한 트랜잭션으로 가져오는 RPC.
- 모든 테이블은 소유자 RLS 적용. 조회 view는 `security_invoker`. 원장 쓰기는 service role만 가능하며 사용자는 본인의 복기 메모만 수정 가능.
- 표준 JSON 가져오기는 부분체결별 키, 통화별 잔액, Decimal 및 시간대 검증, 미완료 배치 거부, 반복 가져오기 중복 방지, 최신 정정 보호를 제공.
- 로컬 설정: `config/trade_journal.json`. 오전 6시/오후 4시는 해당 시점까지 관측한 데이터이며 거래일 전체 완료를 뜻하지 않음. 이후 거래는 다음 수집에서 보완.
- 저장 구조를 현재 self-host Supabase PostgreSQL 15.8에 적용함. 실제 계좌번호·거래·잔액·키를 삽입하지 않음.

## 아직 연결하지 않은 범위

최신 사용자 확인: 나무 API 신청·발급 및 로컬 키 설정 완료, 키움은 추후 인증 후 추가. 첫 연동은 나무 일반/CMA부터 진행하며 ISA는 추가 대기다. 키움은 `enabled: false`이며 현재 준비상태 검사에서 키움 인증정보를 요구하지 않는다. 나무 인증·계좌목록 조회는 성공했다. 사용자가 이전 IRP 식별을 정정하여 끝자리 2466을 원하는 일반/CMA 계좌라고 확인했으며 로컬 일반계좌 설정에 연결했다. ISA는 아직 추가 전이므로 비활성화했다.

- 증권사 API 인증/실제 계좌 조회, 필드 매핑, 모든 페이지/세션/거래경로 지원 검증은 대기.
- 증권사 수집 어댑터, 실거래 보유잔고 대조, 자동 손익 및 기존 수동 포트폴리오 투영은 미구현.
- 실제 오전 6시/오후 4시 예약 작업은 **미등록**. 설정과 화면의 예정 시각만 반영함.
- 나무/영웅문 원본 CSV/Excel 파서는 아직 없음. 현재 가져오기는 명세에 맞게 정규화된 JSON에 한정됨.
- UI는 현재 연동 대기로 표시하며 API 자동 수집 성공을 주장하지 않음.
- 코드 변경은 로컬 구현이며 사이트 운영 배포는 하지 않음.

## 사용자가 준비할 항목

1. [NAMUH PLUG 이용안내](https://www.nhplug.com/howto-use)에 따라 API 신청 및 APP KEY/Secret 발급. 일반·ISA 조회 지원 여부 확인.
2. [키움 REST 이용안내](https://openapi.kiwoom.com/intro/serviceInfo)에 따라 API 신청, 계좌 키 발급, 실제 수집 컴퓨터/서버의 허용 외부 IP 등록.
3. 인증정보는 로컬 `.env.local` 또는 향후 Keychain에 보관. 채팅/계획서/Git/브라우저에 키·비밀번호를 넣지 않음.

현재 준비상태 확인 명령이 확인하는 **환경변수 이름**:

```text
NAMUH_APP_KEY
NAMUH_APP_SECRET
NAMUH_GENERAL_ACCOUNT
NAMUH_ISA_ACCOUNT
KIWOOM_APP_KEY
KIWOOM_APP_SECRET
TRADE_JOURNAL_USER_ID
```

키움 키가 계좌에 연결되는 인증 방식을 실제 발급 설정과 대조한다. 나무 계좌 값은 실제 API가 요구하는 형식을 확인한 뒤 설정한다. `TRADE_JOURNAL_USER_ID`는 자료 소유자의 Supabase Auth UUID이며 임의로 다른 사용자나 첫 번째 관리자 UUID를 선택하지 않는다.

준비상태 명령은 `.env.local`을 읽고 값은 출력하지 않는다. 필요한 변수 이름 및 매핑 대기 상태만 출력한다. 아직 수집 가능한 상태가 아니므로 exit code 2를 반환한다.

```sh
PYTHONPATH=scripts .venv/bin/python -m investment_ops.journal readiness
```

## 표준 데이터 가져오기

이 기능은 증권사 원본 응답 파서가 아니다. 증권사별 필드/체결 식별자/부분체결/정정 의미를 검증한 정규화 데이터만 사용한다. 테스트 데이터는 실제 계좌에 삽입하지 않는다.

```sh
PYTHONPATH=scripts .venv/bin/python -m investment_ops.journal validate-batch /absolute/path/sanitized-batch.json
PYTHONPATH=scripts .venv/bin/python -m investment_ops.journal import-batch /absolute/path/sanitized-batch.json
```

두 번째 명령은 DB에 기록한다. `SUPABASE_SERVICE_ROLE_KEY`, Supabase URL, 확인된 소유자 UUID가 필요하다. 소유자 UUID는 환경변수 우선이며 `config/trade_journal.json`의 `user_id`에서도 설정 가능하다. 인증정보와 계좌번호는 이 JSON 설정에 넣지 않는다.

표준 배치의 필수 필드:

| 영역 | 필드 |
|---|---|
| 루트 | `schema_version: 1`, `account_alias`, `source: API/MANUAL_IMPORT`, `complete: true`, `observed_at`, `executions`, `cash_events`, `balances` |
| executions | `source_key`, `market`, `symbol`, `name`, `currency`, `side`, `trade_date`, `executed_at`, `settlement_date`, `quantity`, `price`, `gross_amount`, `fee`, `tax`, `status` |
| cash_events | `source_key`, `occurred_at`, `currency`, `kind`, `amount`, `description` |
| balances | `currency`, `cash`, `withdrawable`, `buying_power`, `settlements` |
| settlements | `date`, `amount` |

시간은 시간대가 있는 ISO 8601 문자열, 날짜는 YYYY-MM-DD, 숫자는 십진 문자열로 전달한다. 수수료/세금/출금가능/주문가능/결제일이 없으면 `null`; 배열에 기록이 없으면 `[]`. 잔액이 조회되지 않았을 때 가짜 0 잔액을 생성하지 않는다.

`source_key`는 계좌/증권사 원본 거래일/검증된 개별 체결 또는 현금 이벤트 ID에서 안정적으로 생성한다. 전체 계좌번호를 포함하지 않는다. 동일 주문의 부분체결은 다른 키를 가져야 하며 정정은 기존 키로 연결한다. 미체결 주문 취소를 체결 취소로 변환하지 않는다.

`observed_at`은 실제 관측 시각이다. 과거 자료를 나중에 다시 가져올 때 관측 시각을 임의로 현재로 바꿔 최신 정정을 덮어쓰지 않도록 원본의 버전/관측 증거와 대조한다. 이전 배치 전체는 감사이력으로 보존한다.

## 검증 기록

- Python 기존 기반+새 단위 테스트 35개 통과.
- 독립된 임시 PostgreSQL DB에서 통합 테스트 3개 통과: 부분체결/재실행/최신 정정/메모 보존, 소유자 RLS 및 view/RPC 권한, 실패 시 전체 롤백. 테스트 DB는 삭제함.
- 새 화면/Sidebar 대상 ESLint 통과.
- 전체 `npm run lint`: 기존 전체 탐색 중 Node heap 메모리 부족으로 종료.
- 전체 `npx tsc --noEmit`: 기존 `next.config.ts`, wiki attachment route, market-index 및 차트 컴포넌트 타입 오류로 실패. 새 매매일지 파일 오류는 출력되지 않음.
- 기본 Turbopack build는 장시간 진행이 멈춰 중단. `npm run build -- --webpack` 성공, 새 매매일지 경로 포함. 기존 설정은 빌드에서 타입 검사를 생략하므로 별도 tsc 실패 기록을 함께 유지한다.
- 로컬 production server 실행 후 브라우저에서 예정 시각·3개 계좌·필터·로그인 필요 상태와 레이아웃 확인. 로그인한 실제 거래/메모 UI 검증은 미수행.

### 작업 로그 — 2026-10-12

키 설정 후 조회 검증: 나무 인증 성공 및 계좌목록 응답코드 `00000` 확인. 운영 1개/모의 3개가 표시됐으며 사용자가 운영계좌는 원하는 일반·ISA가 아닌 개인형 IRP라고 확인했다. 사용자 회신 전에 진행 중이던 잔고 탐색 요청은 완료됐지만 숫자/종목/전체 계좌번호를 출력·저장하지 않았고 DB 쓰기는 수행하지 않았다. HTTP/응답 필드 탐색은 대상 계좌 검증을 대체하지 않는다. 이후 잔고 탐색은 사용자가 식별해 로컬에 설정한 계좌와 정확히 일치할 때만 허용하도록 변경했다. 계좌유형 코드 01/02는 운영 환경을 뜻하며 일반/ISA/IRP 구분으로 사용하지 않는다. 자동 수집은 계속 미등록이다.

공식 계좌목록 설명은 “API 이용 가능한 계좌목록을 조회합니다. (모의투자 계좌 포함)”이다. 고객의 모든 계좌를 보여주는 API로 가정하지 않는다. 일반·ISA가 목록에 없는 이유와 등록/이용 가능 여부는 현재 확인되지 않았으며 나무 포털 또는 공식 Q&A 확인이 필요하다. 공개 이용안내만으로 특정 계좌 연결 버튼/절차를 확정하지 않았다. 인증/조회 전용 안전성 테스트 및 미식별 운영계좌 잔액조회 차단 테스트 5개 통과.

후속 범위 변경: 사용자가 나무만 신청 완료했다고 알렸으며 키움은 배우자 계좌로 추후 인증 후 추가하기로 했다. 나무 일반·ISA를 첫 연동 대상으로 설정했고 키움을 비활성화했다. 나무 인증정보의 로컬 설정 여부만 값 없이 검사했으며 아직 미설정임을 확인했다. 다음 단계는 로컬 키 설정 후 나무 조회 검증이다.

사용자 구현 요청과 시각 변경을 반영했다. 양사 API 미신청을 확인하고 독립적인 일지 DB/표준 JSON 가져오기/UI를 구현했다. 테스트는 실제 증권사 샘플을 대체하지 않는 합성 자료로 수행했고 임시 DB를 삭제했다. 검증 후 additive schema만 self-host DB에 적용했고 실거래/잔액/계좌 정보를 삽입하지 않았다. 기존 수동 포트폴리오 및 투자규칙 모드는 변경하지 않았다. 다음 작업은 키 발급 후 실계좌 조회 범위·필드 검증과 수집 어댑터/예약 작업 구현이다.
