1. 사용자는 2026-09-14에 “계획대로 읽고 실행하라”고 명시했고, `mhoon@ibinvest.co.kr` 계정을 위키 허용 계정으로 지정했다. 코드·마이그레이션은 로컬 Supabase DB에 적용했으며 배포·외장 하드 작업은 아직 수행하지 않았다.
2. 새 사용자 메시지에서 구현을 요청하면 그 최신 요청을 우선해 작업 범위와 이 문서 상태를 갱신한다. 과거의 계획 단계 문구를 이유로 이미 받은 구현 요청을 다시 승인받지 않는다.
3. 사용자는 본인 한 명이다. 다른 일반 사용자뿐 아니라 다른 웹사이트 관리자도 위키를 사용하거나 읽을 수 없어야 한다.

6. 외장 하드는 사용자가 나중에 마련한다. 로컬 백업과 외부 장치 복구본 확보를 구분하며, 외장 하드 때문에 독립적인 구현·시범 사용을 멈추지 않는다.
7. 저장소에는 위키 작업과 무관한 기존 미커밋 변경·추가·삭제가 많다. 정리하거나 되돌리지 않는다.
8. 사용자가 스크린샷 단독 재현의 한계를 지적한 뒤 `.webarchive`를 제공했다. HTML·CSS 분석은 완료했고 계획 1.2에 반영했다. 같은 파일을 다시 요청하지 않는다. CSS 선언과 실제 브라우저 계산·동작 검증은 구분한다.
9. 전체 원본은 `references/source/`에 로컬 보존·Git 제외. 다른 AI가 참고할 분석 보고서·선별 CSS 근거는 버전 관리 대상이다.

## 미검증·주의 사항

- 나무위키 직접 브라우징은 도구의 사이트 접근 정책으로 차단되어 우회하지 않았다. 현재 근거는 사용자 제공 스크린샷과 HTML·CSS 저장본의 정적 분석이다.
- 모바일 이미지는 163px 폭으로 축소되어 실제 viewport·터치 영역을 측정할 수 없다. CSS의 기본 글자 크기는 저장본에서 확인했다.
- 글꼴 선언은 확인했지만 실제 선택된 폰트는 미확인이다. 목차 details·각주 앵커·절 접기 상태 CSS·편집 링크는 확인했지만 실제 조작·편집 페이지는 검증하지 않았다.
- Docker 소켓 읽기 권한 제한으로 실행 중인 컨테이너를 직접 확인하지 못했다.
- Vercel 현재 배포 환경변수·운영 DB 정책·최근 자동 백업·전체 복원 성공은 미검증이다.
- 기존 루트 스크롤 제한, `/`·`/login`만 대상으로 하는 미들웨어, 공개 `stocks` 버킷을 위키 보호 기능으로 간주하지 않는다.
- 현재 빌드 설정은 타입 오류를 무시할 수 있으므로 빌드 성공과 타입 검증 성공을 구분한다.
- 서비스 역할 키·DB 관리자 권한은 일반 사용자 접근 테스트의 대체 수단이 아니다.
- 단기 서명 URL은 최초 제안이었으나 본인 전용 조건 반영 후 기본안에서 제외했다. 최신 설계는 인증된 파일 다운로드다.
- 마이그레이션은 로컬 Supabase DB에 적용했고 `wiki_access`에 지정 계정 하나를 등록했다. production Vercel 배포와 외부 접근은 별도 검증이 필요하다.
- 현재 `.env.local`의 Supabase URL은 `http://127.0.0.1:8000`이고 Docker Supabase가 이 Mac에서 실행 중이다. 공개 Vercel 앱은 브라우저 번들에서 `https://supabase.apextraders.xyz`를 Supabase API로 사용한다. 공개 번들에는 로컬 앱과 동일한 anon key가 포함돼 있고, 사용자가 생성된 문서를 공개 환경에서 확인했다. 이는 공개 주소가 이 self-host Supabase를 외부에 연결한 경로라는 현재 증거와 일치한다.
