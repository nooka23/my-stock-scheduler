# 데일리 리뷰 뉴스 수집 계획

## 목적

기존 RSS 수집기를 후보 기사 수집기로 재사용하고, 시장 리뷰에 중요한 사건만 날짜별로 보존한다. 데일리 리뷰에서 중요 사건과 근거 기사 링크를 다시 열람할 수 있게 한다.

## 합의된 저장 원칙

- 수집된 모든 RSS 원문을 DB에 영구 저장하지 않는다.
- 중요도 기준을 통과한 사건만 날짜별로 저장한다. 표시 건수 상한은 두지 않는다.
- 같은 사건을 다룬 여러 기사는 하나의 사건 카드에 묶고, 각 기사의 제목·출처·발행 시각·원문 URL을 근거로 보존한다.
- 사건 카드에는 AI 요약, 중요도, 중요하다고 판단한 이유, 분류를 저장한다.
- 기사 전문과 RSS 본문 조각은 영구 저장 대상에서 제외한다.
- 뉴스가 0건인 경우와 소스 수집이 실패한 경우를 구분해 표시한다.

## 기존 구성과 재사용 범위

1. `/Users/myunghoon/article-scrapper/fetch_news.py`는 기존 CLI, RSS 파싱, URL 중복 제거, Google News 링크 해석, 24시간 기본 수집 창을 유지한다.
2. `/Users/myunghoon/article-scrapper/output/raw_articles.json`과 manifest는 수집 원재료와 source coverage를 전달한다. 이 파일은 최신 실행 스냅샷이므로 과거 보관소로 취급하지 않는다.
3. `scripts/company_intelligence/providers/rss_file.py`의 파일/manifest 일치 검증과 부분 실패 의미를 재사용한다.
4. 기존 P2-08 뉴스 연결·묶음 코드는 회사 중심이므로, 시장 전반 뉴스의 중요도 선별과 사건 묶음 규칙은 데일리 리뷰 도메인에 별도로 둔다.

### 출처 국가와 기사 시장 범위

- 기존 `sources.yaml`의 `region`은 언론사/피드 출처 국가 태그로 유지한다. 이 값을 뉴스가 다루는 시장의 국가로 간주하지 않는다.
- 후보 기사 또는 사건에는 별도의 `market_scope`를 둔다. AI가 기사 근거를 바탕으로 `US`, `KR`, `China/Asia`, `Global`, `Multi-region`, `Unknown` 등으로 분류하고, 분류 근거와 확신도를 함께 기록한다.
- 집계와 coverage 화면은 `source_region`(출처 구성)과 `market_scope`(기사 주제의 시장 범위)를 구별해 표시한다. 미분류/불확실 기사는 `Unknown`으로 남기고 임의로 추정하지 않는다.

## 수집부터 화면까지

`RSS 실행 → raw_articles.json + manifest → 스냅샷 및 source coverage 검증 → URL/유사 보도 중복 제거 → 중요도 분류와 사건 묶기 → 기준 통과 사건만 날짜별 저장 → /daily-review 뉴스 카드 표시`

- 소스별 실패가 하나라도 있으면 실행 전체를 완전 성공으로 표시하지 않는다. 결과가 일부 있더라도 화면에 부분 수집 상태와 실패 소스를 보여준다.
- 선별은 한 번에 처리하기 어려운 분량이면 여러 묶음으로 나누되 전체 입력을 처리한다. AI 요청 단위 크기는 조절할 수 있지만 최종 결과 수를 자르지 않는다.
- 모델 결과는 근거 기사 제목/요약에 연결하고, 출처에서 확인되지 않는 시장 영향 주장은 만들지 않는다. 상충 보도나 낮은 신뢰도는 별도 상태로 남긴다.
- 중요도 기준은 거시경제·중앙은행·정책·지정학·공급망·주요 산업·대형주에 실질적 영향을 줄 수 있는 새 사건을 우선한다. 구체 점수 경계는 저장 전 오프라인 선별 미리보기로 보정한다.

## 날짜와 재실행

- 원본 수집 구간(`window_start`, `window_end`)과 리뷰 날짜를 둘 다 보존한다. 날짜 경계를 KST 기준으로 확정하기 전까지 원본 시간 구간을 임의로 하루에 맞춰 자르지 않는다.
- 같은 입력 스냅샷을 다시 처리해도 중복 사건/기사 링크가 생기지 않도록 실행 ID, 리뷰 날짜, 사건 식별 키 및 URL hash를 기준으로 멱등 저장한다.
- 중요도 결과를 다시 생성할 때는 모델/프롬프트 버전을 기록하고, 기존 결과를 조용히 덮지 않는다.

## 구현 단계

| 단계 | 결과 | 실행 범위 |
|---|---|---|
| 1. 저장 표본 coverage 점검 | 저장된 표본 수집 범위와 미국장 주요 뉴스 대조 완료. 중요도별 AI 선별/사건 묶음 미리보기는 다음 단계 | 파일 읽기만, RSS 재수집·AI API·DB 쓰기 없음 |
| 2. 결과 계약과 날짜별 저장 경계 | 중요 사건, 근거 링크, 실행별 coverage 저장 형식과 공개 읽기 범위 | 추가 마이그레이션은 만들되 운영 DB에는 적용하지 않음 |
| 3. AI 선별 연결 | 전체 후보를 분할 평가하고 기준 통과 사건만 생성 | 선택한 AI 제공자, 예상 비용, RSS 콘텐츠 전달 범위를 먼저 명시 |
| 4. 운영 수집과 화면 연결 | 정기 실행, 멱등 저장, 부분 실패 표시, `/daily-review` 실제 뉴스 렌더 | 소스 약관/재배포 조건 확인 후 활성화 |

## 현재 상태와 제한

- 기존 수집기는 파일 기반이고, 마지막 JSON/manifest 스냅샷을 새 수집 결과로 덮어쓴다.
- 앱의 `NEWS_RSS_FILE` provider는 `SHADOW_ONLY`; P2-07 입력 검증과 P2-08 클러스터 분석 증거는 FIXTURE/local-only다. 실제 RSS 재수집, LLM, durable DB apply, scheduler는 활성화되어 있지 않다.
- 기존 데일리 리뷰 페이지는 여전히 합성 뉴스 예시를 표시한다. 이 문서는 실제 수집이나 DB 변경을 했다는 뜻이 아니다.
- 공개 데일리 리뷰에 기사 제목, AI 요약, 링크를 표시할 수 있는 범위는 각 뉴스 제공처 조건을 검토해야 한다. 기사 전문은 저장하거나 노출하지 않는다.

- 2026-09-23: 현재 저장 표본(1,208건)을 전일 미장 종합 기사와 대조했다. 핵심 뉴스 테마는 잡혔지만 Reuters Google News 링크 150건 미해결, 기사 요약 제목 수준, 결과 100건 RSS 상한 가능성을 기록했다. 상세 기록은 [미국장 뉴스 coverage 점검](./daily-review-news-audit-2026-09-23.md)에 있다. 아직 AI 중요도 미리보기·수집기·DB는 실행/변경하지 않았다.
- 2026-09-23: 사용자의 정정에 따라 기존 `region`을 언론사/피드 출처 국가로 명확히 하고, 기사의 시장 범위는 별도 `market_scope`로 분류하는 원칙을 추가했다. 저장 표본의 지역별 숫자를 미국 시장 뉴스의 비중으로 해석하지 않도록 감사 기록을 수정했다.
